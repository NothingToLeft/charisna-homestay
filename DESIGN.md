# CHARISNA KOST interface

CHARISNA KOST is an Indonesian property operations app. Its identity is emerald, clear typography, and practical information density. Preserve existing workflows, Firebase roles, encrypted storage, and native wrappers while improving presentation.

Use Plus Jakarta Sans with a system fallback. Light surfaces use a quiet green-gray background, white work areas, dark green text, and emerald for primary actions. The existing light, dark, and system theme options share semantic variables in `public/interface.css`. Public tenant and catalog pages use the same scale without loading owner data or navigation.

ENERGY 1 / RHYTHM 2 / MOTION 1. Operational data and readable controls matter more than decoration. Sidebar navigation identifies workflows. Settings services are grouped as Penghuni, Pemasaran & komunikasi, and Pembayaran & laporan. Service entries use descriptive rows instead of a wall of indistinguishable buttons. A hairline separates groups; shadows distinguish modal elevation. No new visual assets, decorative gradients, fictional claims, or unnecessary animation are required.

Dialogs use a clear heading and close action, labeled fields, readable help, visible focus, and primary/destructive button treatments. Native dialog keyboard behavior remains intact. Tables scroll within their work area on narrow screens; horizontal toolbars wrap. Controls have a minimum 44 CSS px target. Existing statuses retain text labels rather than relying only on color.

UI UX Pro Max's dashboard guidance informed spacing, density, and form interaction. Its generated marketing hero and property-promotion suggestions were inappropriate for internal operations and were not used. Antislop filters apply to implementation and visual verification.

## Verification scope

Isolated browser fixtures exercised all ten owner tabs at 320, 375, 768, 812 landscape, and 1440 px widths. All seven service dialogs opened and closed at phone, tablet, and desktop sizes. The existing WhatsApp connection regression checks cover masked codes, live status, rejection, network failure, failed-save rollback, delivery uncertainty, and keyboard focus.

Tenant, catalog, and cleaner views were tested at four widths using simulated Firestore responses. Tenant complaint submission and cleaner checklist updates used mock writes only. No customer account or real message was used. These checks do not replace physical Android testing, live payment processing, or native app releases.
